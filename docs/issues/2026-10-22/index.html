Local Allow, Global Deny: per-action authorization does not compose in LLM agents  —  The paper shows that a guardrail screening each tool call in isolation cannot catch some policy violations that span several executions; relational purpose violations need cross-execution monitoring. A solver-based tool generates minimal witnesses. Across nine LLM judges, the per-action view approved the witness almost always, yet the same models flagged it when shown both executions together. None of six surveyed guardrails monitors across executions.
Takeaway: Relevant to your guardrails and agent-observability work: it argues for trace-level, not call-level, checks.
arXiv: yesterday · 12m
VeriEvolve: evaluator-first evolution for tool-using agents  —  VeriEvolve first synthesizes challenge states and an executable evaluator from the task instruction, freezes it as the fitness signal, then evolves the agent workflow, revising the evaluator between rounds from strong and weak runs. On 30 MCPMark Filesystem tasks, externally verified success rose from 6/30 to 18/30 for GLM-5.2 and 27/30 to 30/30 for Claude. Refinement removed all three false positives.
Takeaway: Connects to your prompt-optimization interests (GEPA-style loops) by showing why the evaluator must be built and calibrated before optimizing.
