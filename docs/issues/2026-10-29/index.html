This week's papers keep returning to what surrounds the model: recursive harnesses, context compaction off the critical path, zero-trust confinement and MCP gateway design. On evaluation, TRACE and the reliability study both ask whether a score change reflects the agent or the measuring setup.

arXiv (Hugging Face Daily Papers): Oct 9 · 8m
AgentSWE: can coding agents build the agent you actually want?  —  Coding agents are increasingly asked to build other agents, but no benchmark checked whether the delivered agent meets the requirement. AgentSWE has 25 tasks across creating, editing and optimizing agents, graded on held-out cases with rubrics and hard pass/fail gates. Across several models and harnesses, none comes close to delivering what a requirement asks. Failure modes include overfitting to visible cases, hollow runtimes behind complete-looking code, and unsupported completion claims. Limitation: only 25 tasks. Public code on GitHub.
Takeaway: Directly relevant to agent evaluation: held-out, rubric-graded acceptance tests and the named failure modes (overfitting, false completion claims) are checks to reuse in your harness and trace evaluation.
arXiv (Hugging Face Daily Papers): Oct 9 · 9m
Harness^2: recursive agent harnessing without ground-truth verifiers  —  Agent harnesses are hand-tuned and hard to improve on unseen tasks with no verifier. Harness^2 refines the harness per task with a contrastive Propose-Probe-Compose step, then distils those edits into a continual-improvement harness. One step improved GLM-5 and Gemini 3.5 Flash over base harnesses on three benchmarks: up to 11.5 points on WorkBuddy-Bench, 4.5 on JobBench, 11.8 points on LAB. Gains grow with recursion budget. Listed under Google; ranks 125 upvotes on Hugging Face trending; code at google-research/harness2.
Takeaway: Speaks to your harness and prompt-optimization work: verifier-free harness edits and a persistent improvement harness are an alternative to GEPA-style optimization; check how much extra compute the recursion costs.
Microsoft Research (preprint): Oct 20 · 12m
CompactionBench and APEC: moving context compaction off the critical path in coding agents  —  Harnesses usually compact context synchronously, which delays the agent and breaks prefix-cache reuse. Microsoft Research analysed 13.5M GitHub Copilot agentic coding sessions (760M LLM calls): only 7.8% of sessions compact, yet they use 44.2% of all tokens. The authors add CompactionBench and APEC, which summarizes finished trajectory segments in the background and appends them to a stable prefix. APEC cuts total cost by up to 25.4% and execution time by 9.6%. Evaluated on a benchmark they built from software release histories, not live production traffic.
Takeaway: Directly relevant to your context-engineering and long-horizon agent harness work: it shows compaction cost and cache behaviour at production scale and a harness-agnostic way to move summarization off the critical path.
arXiv (cs.CR): Oct 10 · 15m
Zero-Trust Agent Cells: confining a coding agent by the object it acts on, not the name  —  Many exploits on deployed coding agents arise because a permission check approves a name (a path or argument vector) and a later step resolves it to a different object, such as a symlink target. ZTAC runs the agent in a kernel sandbox whose only route to files, programs and network is a broker that decides on the resolved object, with one-use approvals. Against 74 attacks, a tool allowlist loses 66 and allowlist plus command sandbox loses 56; ZTAC loses 2 and holds 14 for review. Prototype is macOS-only, and it completes 4 of 7 workflows.
Takeaway: Gives concrete numbers for the sandboxing and permission layer of a production agent runtime, and an argument that guardrails must live outside the model, which bears on your agent guardrail work.
arXiv (cs.CL; AI Measurement Science Workshop at COLM 2026): Oct 8 · 8m
TRACE: is a score change the agent, or the evaluation? A protocol for diagnosing verifier brittleness  —  Verifier scores serve as both benchmark metrics and training rewards, so a score change is often read as a capability change. The author proposes TRACE: mutate one part of an evaluation, compare paired runs, check whether behavior changed, and rescore unchanged trajectories. On tau2-bench with four LLM agents and 88 new tasks, renaming tools or reformatting outputs moved reward by at most 0.10 in seven of eight agent-change pairs, misleading tool names cut reward by 0.20-0.44, and identical reruns flipped 15-36% of task outcomes. Two frontier LLM judges disagreed with each other on 57% of the same records.
Takeaway: A concrete recipe for your agent-evaluation work: before trusting a trace-level score change, rerun identically and rescore fixed trajectories to separate harness or judge effects from real agent change.
arXiv (cs.AI): Sep 30 · 10m
Agent Evaluation Reliability: more tasks will not always fix an agent leaderboard  —  Agent leaderboard ranks mix model, scaffold and task effects. The authors (Hardy, Azam, Reuel, Kochenderfer, Koyejo) fit a Bayesian variance-decomposition to 22 benchmarks from the Holistic Agent Leaderboard and Harbor Index. Fixed model-scaffold systems rank reliably (0.935-0.994) but underlying-model reliability is 0.148-0.841; unlimited extra tasks add at most 0.097 when scaffold coverage limits it. Pooling benchmarks lifts projected cross-task reliability from 0.44 to 0.75 and can cut cost by up to 83%. Results are projections from the fitted framework on existing sparse leaderboards.
Takeaway: Useful when designing evaluation suites for a production agent harness: it argues for varying scaffolds and pooling benchmarks rather than only adding tasks, depending on whether the claim is about the model or the deployed system.
