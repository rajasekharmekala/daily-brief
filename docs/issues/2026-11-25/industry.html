Google Workspace Updates: yesterday · 4m
Google Workspace MCP servers and Workspace CLI reach general availability  —  Google made its managed Workspace Model Context Protocol (MCP) servers and official Workspace CLI generally available on November 24, paired with standardized usage tiers, a new Workspace AI Tools Addendum, and expanded admin controls. The Google-hosted MCP servers give cloud and web agents pre-built tools across Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks, with Keep coming soon. The Workspace CLI brings those same governed tools directly into developer terminals, VMs, and containerized sandboxes without custom glue code, giving teams a sanctioned path for production agent access.
Takeaway: Directly streamlines your personal automation and MCP-based agent workflows across Gmail, Drive, and Docs without maintaining custom OAuth wrappers.
Microsoft Foundry Blog: yesterday · 6m
Microsoft Foundry Ignite 2026 ships GA A2A tool, voice agents, and trace-to-optimizer loop  —  Microsoft announced its Ignite 2026 Microsoft Foundry release on November 24, moving multi-turn evaluation, Insights, voice agents, external-agent registration, hosted-agent egress controls, and the Agent2Agent (A2A) tool to general availability alongside the Foundry Dev Pack and Foundry CLI (`azd ai`). In preview, Foundry now links trace Insights directly into Agent Optimizer to learn reusable skills from real conversations and search for cheaper configurations that still meet a quality bar, alongside rubric evaluators, human annotation, and Programmed Training. Several governance and cost-control modules remain in preview.
Takeaway: Connects your core interests in agent trace evaluation, prompt optimization, A2A interoperability, and voice agents in one production runtime release.

Takeaway: Relevant to your GitHub Copilot workflow and agentic code-review evaluation, showing how review depth can be dynamically routed by PR risk.

Models and leaderboards

Cognition: yesterday · 4m
Cognition releases SWE-2.1, a pure-RL coding model trained on Kimi K3  —  Cognition released SWE-2.1 on November 24, an upgrade over SWE-2 trained with pure reinforcement learning on top of Kimi K3 and focused on general intelligence and long-horizon workflows. In vendor-reported evaluations, SWE-2.1 jumps from 24.2 to 50.0 on Terminal-Bench 4.1, from 24.1 to 41.3 on FrontierCode 2.0, from 17.0 to 44.0 on ProgramBench, and from 12.1 to 27.3 on ExploitGym. While those gains more than double SWE-2 across several suites, SWE-2.1 still trails frontier baselines such as Claude Opus 5.5 (65.8) and Gemini 4 Neon (65.2) on Terminal-Bench 4.1.
Takeaway: Directly relevant to your focus on RL-trained coding agents and long-horizon benchmark tracking on Terminal-Bench 4.1.
Hugging Face (PrismML): yesterday · 5m
PrismML releases Apache 2.0 Ternary Bonsai 2.5 27B (5.93 GB) for local agentic tool use  —  PrismML released Ternary Bonsai 2.5 27B under Apache 2.0 on November 24, a ternary-quantized (1.76 bits/weight, 5.93 GB vs. 53.8 GB FP16) agentic model built on Qwen3.8-27B with a 262K context window for llama.cpp and MLX. In vendor-reported benchmarks, it averages 77.2 across five tool-calling suites (τ²-Bench, τ³-Bench, BFCL v3/v4, AppWorld) versus 77.7 for FP16, and hits 75.6 on SWE-bench Verified (up from 60.8 on Bonsai 2) and 60.1 on Terminal-Bench 2.1. Multi-token prediction (MTP) draft-head variants speed up GPU decode by 1.5-1.8×, though `PTQ1_0` upstream llama.cpp support is still under review.
Takeaway: Shows how sub-6 GB open-weight models are closing the gap to FP16 on agentic tool calling and SWE-bench for local laptops.
RadixArk Blog: 7 days ago · 5m
RadixArk releases DaisyRose-27B, a pure-RL Qwen3.8-27B agent model trained in 18 days  —  RadixArk released its debut open-weight model DaisyRose-27B on November 18 in BF16, FP8, and NVFP4 checkpoints (Apache 2.0), post-training Qwen3.8-27B solely with asynchronous reinforcement learning via its open-source Miles framework—with no supervised fine-tuning or distillation. Trained for 18 days on 144 H200 GPUs (128 running agent inference, 16 updating weights) over 1,200 curated long-horizon tasks spanning up to 1M-token sessions and 1.5-hour sandboxes, DaisyRose-27B raises vendor-reported Terminal-Bench 4.1 pass@1 from 5.6% to 12.0%. While still far below frontier models, it demonstrates meaningful long-horizon RL gains on a modest compute budget.
Takeaway: Relevant to your interest in RL post-training efficiency, asynchronous agent rollouts, and Terminal-Bench 4.1 tracking.
Hugging Face (inclusionAI): 2 days ago · 4m
inclusionAI open-weights MIT-licensed Ling-3.2-air (124B/5.5B MoE) for workflow automation  —  inclusionAI released Ling-3.2-air under an MIT license on November 23, a native multimodal hybrid-linear MoE model with 124B total parameters and 5.5B active per token (35 KDA + 7 Gated MLA layers, 512 routed experts) plus a day-0 SGLang container image. In vendor-reported evaluations against Ling-3.0-flash-VL, AutomationBench-AA climbs from 15.7% to 61%, AA-Briefcase v1.1 Elo rises from 987 to 1340 (+353), Terminal-Bench 4.0 moves from 0% to 27%, and Artificial Analysis Intelligence Index v5.0.1 reaches 23. On Harvey LAB-AA v1.1, criterion pass rate hits 87.7%, though all-pass drops from 8.3% to 0.8% after hallucination checks.
Takeaway: Notable permissive-license MoE checkpoint targeting workflow automation and terminal tasks with just 5.5B active parameters.
GitHub (Tencent-Hunyuan): Nov 17 · 4m
Tencent open-weights Hy4 flash (220B/12B MoE) with 1M context and Engram embeddings  —  Tencent released Hy4 flash, Hy4 flash-FP8, and Hy4 flash-base as open-weight multimodal models (text and image inputs, 1M-token context) under the custom Tencent Hy License. The architecture totals 220B parameters—155.5B in a 42-layer LatentMoE backbone, 63.5B in learned bigram/trigram Engram hash-lookup embeddings, 0.43B ViT, and a 0.85B 5-layer DFly2 speculative drafter—while activating about 12B parameters per token (11.3B text + 0.43B vision). It interleaves sparse attention and 512-token sliding-window attention at a 1:3 ratio using MLA and ships with vLLM and SGLang deployment guides; note the non-OSI custom license.
Takeaway: Interesting architectural blueprint for low-cost 1M-context MoE inference combining Engram hash lookups with built-in speculative decoding.

Open source and developer ecosystem

GitHub (pydantic/pydantic-ai): today · 4m
Pydantic AI v2.75.0 gates workspace instruction authority and improves model fallback handling  —  Pydantic AI released `v2.75.0` on November 25 with two notable runtime safety and reliability changes. First, `RepoContext`, `Skills`, and `Memory` now keep workspace files below `'operator'` authority out of system instructions (adding `lowest_authority_under`), instead surfacing lower-authority files via file tools, `list_skills`/`load_skill`, or framed data to harden against untrusted repo content. Second, empty streams or invalid/schema-mismatched OpenAI Chat completions now raise `ModelEmptyResponseError` and `ModelInvalidResponseError` so `FallbackModel` triggers automatically. Durable Temporal and DBOS workflows require draining in-flight runs or versioning workers before upgrading.
Takeaway: Directly informs your agent harness and runtime architecture with concrete authority boundaries for skills/memory and cleaner fallback semantics.
Hugging Face Blog: 5 days ago · 6m
Hugging Face introduces RL-trained harness adapters to tune open models for specific agent harnesses  —  Hugging Face published a reusable recipe and datasets on November 20 (144 Hub upvotes) for training lightweight per-harness RL LoRA adapters using `AsyncGRPOTrainer` directly inside agent harnesses—specifically Pi, OpenCode, and Hermes Agent—while keeping base model weights frozen. On Terminal-Bench 2.1 with the Pi harness, adding a custom RL LoRA adapter to Qwen3.8-27B lifts pass@1 from 39% to 55% while cutting average token usage from 2.9K to 1.5K per task, largely by reducing unnecessary reasoning loops and redundant tool calls. Adapters remain tied to the target harness and task distribution.
Takeaway: Directly actionable for your agent harness engineering: shows how small RL LoRA adapters boost pass rates and halve token cost per harness.
GitHub (openai/openai-agents-python): 2 days ago · 3m
OpenAI Agents SDK v1.0.0-alpha.2 adds cross-worker approval resumption and Codex recovery  —  OpenAI shipped `openai-agents` `v1.0.0-alpha.2` on November 23 as a GitHub-only wheel preview bundling the native Codex runtime for Python 3.10–3.14. The release enables resuming conversations and pending approvals across workers with either the Responses API or Codex, recovering supported native Codex command and edit approvals, configuring tool execution hooks, filtering available function tools, and opting into Runner text redaction and detailed operation tracing. Because Alpha.2 introduces new persisted state formats, maintainers warn operators to upgrade checkpoint readers before writers.
Takeaway: Maps directly to your production agent runtime, durable approval recovery, and tracing work across Codex and Responses backends.
vLLM Blog: yesterday · 5m
vLLM launches vLLM-GR for serving generative recommendation models with shared KV-cache beam search  —  The vLLM team introduced `vLLM-GR` on November 24, an open-source serving extension built on vLLM's execution engine and paged KV cache for generative recommendation models such as OneRec-1.7B, HSTU, and OneTrans on NVIDIA GPUs and Ascend NPUs. Instead of treating each candidate path separately, `vLLM-GR` shares the cached user interaction history across candidate paths and executes successive beam-search steps directly on the accelerator within a single request (e.g., generating 128 candidate semantic IDs), cutting redundant computation and host-device synchronization overhead when moving recommendation workloads from offline evaluation to online serving.
Takeaway: Useful inference-engine update showing how vLLM's paged KV cache and accelerator-side beam search extend beyond standard chat serving.
