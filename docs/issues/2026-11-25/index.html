Compressed 76,000-line Lean 4 Riemann Hypothesis proof passes MIT verification checks  —  Following the November 23 report that an Anthropic mathematician and Claude produced a 17-million-line Lean 4 proof of the Riemann Hypothesis, a dramatically compressed version (`github.com/lsernau/grh-lean`, commit `72fead10`) was published on November 25. It ships in two Lean v4.35.0 editions—an 803-file, ~300,000-line "readable" build and a 794-file, ~76,000-line "compact" build—proving the same five Mathlib theorems. MIT's Andrew Sutherland verified both compile cleanly using only the three standard axioms (`propext`, `Classical.choice`, `Quot.sound`) and pass independent checkers `nanoda`, `con-leche`, and `con-ron`, while paranoid comparator runs remain in progress.
Takeaway: Directly extends your interest in AI mathematical reasoning, formal proof verification, and Lean 4 verifiers—and pairs with today's Deep Dive on autoformalization.

arXiv: yesterday · 8m
Lazy Agents Answer Against Their Own Beliefs: Reinforcement Learning with Verifiable Beliefs  —  This paper tackles agent laziness—committing to answers before gathering sufficient evidence. Because outcome-only RL rewards lucky guesses equally, the authors introduce Reinforcement Learning with Verifiable Beliefs (RLVB), which uses simulator-computed posteriors to reward gathering more evidence while multiple answers remain viable and committing once evidence suffices, with no LLM judge. Across three VLMs and three benchmarks, RLVB improves the base model in all nine settings by 17.1% on average, beats LLM-judge PPO by 9.3% using 1.6x fewer GPU-hours, and cuts premature commits from 3–68% down to 0.1–2.2%. A key limitation is its reliance on simulators that can compute exact step-level posteriors.
Takeaway: Directly informs your production agent runtime and evaluation work by showing how verifiable belief-stopping rewards curb premature tool termination without an LLM judge.
arXiv: 4 days ago · 7m
Don't Sleep, Keep Watch: Proactive Perception for Computer-Use Agents  —  This paper addresses the perception-action gap in vision-language computer-use agents, where slow turn-by-turn snapshots go stale on dynamic UIs. The authors introduce NightWatch, a plug-and-play framework pairing any VLM agent with NightWatch-0.8B, a lightweight System-1 watcher that continuously monitors interface changes without modifying the agent's model, prompt, or action space. On OSWorld-Verified, NightWatch cuts non-reasoning wall-clock time by 33% and wasted time by 53% while maintaining task success; on DynaCU-Bench, it lifts large-VLM success from 39.5% to 44.2% while outperforming passive baselines and a System-1 model over 30x larger. Evaluation is currently scoped to screenshot-only desktop and dynamic web benchmarks rather than arbitrary enterprise UIs.
Takeaway: Relevant to your agent harness engineering thread: separating a lightweight streaming watcher from the slow reasoning model cuts stale-state failures and idle wall-clock latency.
arXiv: yesterday · 7m
Delegent: A Multi-Agent Harness That Reduces Cost without Sacrificing Performance  —  Frontier coding agents re-read full contexts at every turn even during routine subtasks. Delegent is a multi-agent harness built on Claude Code where the frontier model retains control of every task but delegates focused legwork—such as reading code, running tests, and searching corpora—to local small language model (SLM) subagents without training any router or custom model. Paired with a 27B FP8 SLM, Delegent reduces frontier API cost by 67% on long-horizon coding and 59% on agentic search with no performance loss; even a laptop-sized 2B SLM cuts coding cost by 66% when guided by a short instruction keeping core edits on the frontier model. Savings depend on workload legwork volume and require local hardware to host the SLM.
Takeaway: Directly maps to your Claude Code and agent harness engineering work, offering a zero-training delegation pattern to cut frontier token spend on long-horizon coding.
arXiv: yesterday · 6m
TimeTravelContainer: A Live Forking Sandbox for Stateful Agent Exploration  —  Agents driving stateful tools like shells or simulation engines need fast branching and backtracking, yet existing microVM or kernel-patched sandboxes require disk serialization or root privileges. TimeTravelContainer (TTC) is a rootless container runtime that live-forks a running container—processes, memory, filesystem, and network—using copy-on-write semantics so clones share read-only memory pages without kernel patches, hardware virtualization, or root access across Linux, macOS (Apple Silicon), and Windows (WSL 2). Evaluated on two stateful electronic design automation agent flows (MAGE/Innovus and EvoDRC/KLayout), TTC delivers 84.1x faster environment cloning, 31–72% lower memory usage, and 1.7–9.4x end-to-end speedup. Memory savings are strongest when most post-fork tool state stays read-only and may narrow under write-heavy workloads.
Takeaway: Key infrastructure for your agent sandboxing and runtime engineering: rootless CoW live forking enables fast tree search and backtracking on stateful dev environments including Apple Silicon.
arXiv: Nov 10 · 11m
When Evaluators of AI Agents Disagree: Native Scoring, LLM Judges, and Commit-Boundary Checks on tau2-bench  —  Production agent services lack benchmark gold states and rely on LLM-as-judge transcript grading, assuming it tracks ground truth. Across 2,160 tau2-bench airline and retail episodes (plus 120 human-labeled episodes), this study compares gold-state native scoring, an LLM judge (with and without policy docs), and a zero-LLM commit-boundary check verifying whether each database write was expected. The judge achieved 98.2% self-consistency yet agreed with native scoring on only 56.2% of episodes, and passed 10–11 of 11 forbidden-write failures (a stronger judge still passed 6), whereas the commit-boundary check caught all 11. Forbidden writes occurred in 11.1% of ungated episodes and runtime gates failed because digests dropped auth and order fields. Evaluation covers only two domains.
Takeaway: Must-read for your LLM-as-judge reliability and agent-evaluation work: high judge repeatability masks severe state-verification blindness that deterministic commit-boundary checks catch cleanly.
arXiv: Nov 16 · 12m
AuXSpec: Learning to Autoformalize Program Specifications via Executable Postconditions  —  Formal verification in theorem provers like Lean is bottlenecked by writing accurate specifications, and training autoformalizers typically requires costly correspondence proofs. This ETH Zurich paper introduces AuXSpec, a Lean framework pairing declarative postconditions with executable counterparts via type-class resolution or equivalence proofs so unit-test agreement becomes a scalable RL reward. Synthesizing 3,037 LeetCode problems and scaling to 19.5K samples via Codeforces expert iteration, AuXSpec lifts Qwen3.5-9B and Qwen3.8-27B on AuXSpec-Test pass@4 from 0.7% to 82.7% and 14.3% to 84.3%, and boosts out-of-domain Verina pass@4 to 90.5% (beating VeriSpecGen-30B-A3B's 63.9% at pass@10), with weights and a 300-problem proof-reviewed benchmark released. Generalizing beyond algorithmic coding tasks to stateful systems remains an open challenge.
Takeaway: Connects your interest in formal proof verification and Lean 4 verifiers with scalable RL rewards for generating executable, test-checked specifications.
